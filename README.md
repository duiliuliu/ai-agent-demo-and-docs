# Agent 开发渐进式学习项目

> 从单模块能力到企业级整合，像搭积木一样构建 Agent 系统。

## 项目目标

本项目通过**模块化 Demo + 能力整合**的方式，帮助开发者渐进式掌握 Agent 开发的核心技能。每个模块独立可运行，同时提供清晰的边界和接口，供上层章节复用与组合。

## 学习路线

| 章节 | 模块 | 核心能力 | 可复用输出 |
|------|------|----------|-----------|
| [01](01-foundation/) | 基础与环境 | LLM 调用、配置管理、日志追踪 | `skill/base_llm_client` |
| [02](02-tool-use/) | 工具调用 | Tool 定义、Schema、执行、错误处理 | `skill/tool_registry` |
| [03](03-memory/) | 记忆系统 | 短期记忆、长期记忆、向量检索 | `skill/memory_store` |
| [04](04-reasoning/) | 推理策略 | CoT、ReAct、Plan-and-Solve | `skill/reasoning_engine` |
| [05](05-agent-core/) | Agent 核心循环 | OTA 循环、观察、思考、行动 | `skill/agent_loop` |
| [06](06-multi-agent/) | 多 Agent 协作 | 通信模式、角色划分、任务分配 | `skill/agent_swarm` |
| [07](07-workflow/) | 工作流编排 | 状态机、图编排、条件分支 | `skill/workflow_engine` |

| [09](09-integration/) | 综合实战 | 整合前序所有模块的完整应用 | `projects/` |

## 边界要求

### 1. 模块边界
- 每个章节目录**独立可运行**，不强制依赖后续章节。
- 对前序模块的复用通过 `skill/` 目录显式导入，禁止跨章节直接引用 `demo/` 内部代码。
- `skill/` 中的代码必须提供**明确接口**，隐藏内部实现细节。

### 2. 代码边界
- 仅使用公开 API 或开源框架，不绑定特定商业化平台。
- 所有示例需包含 `requirements.txt` 或 `pyproject.toml`，并注明关键依赖版本。
- 示例代码优先保证**可读性**，其次才是性能。

### 3. 文档边界
- 每章 README 必须包含四个部分：**定义**、**示例**、**企业应用注意点**、**应用场景推演**。
- 企业注意点需覆盖：安全、成本、可观测性、容错、合规。
- 禁止在文档中写与学习无关的框架推广或广告内容。

### 4. 整合边界（搭积木）
- `09-integration/` 是前序 `skill/` 的组合层，不得引入新的底层能力。
- 每整合一个模块，需在 `09-integration/README.md` 中记录**组合方式**和**接口契约**。

## 如何开始

```bash
# 1. 按顺序阅读章节 README，理解定义与边界
# 2. 进入对应章节的 demo/ 目录，运行示例
# 3. 阅读并复用 skill/ 中的封装到自己的项目
# 4. 到达 09-integration/ 时，观察如何搭积木
```

## 贡献与迭代

每章学习完成后，建议回顾该章的 `skill/` 输出是否满足：
1. 接口是否稳定？
2. 是否能在不修改内部代码的情况下被复用？
3. 是否包含基础的单测或断言？

若答案为否，优先回滚完善该章 `skill/`，再继续后续章节。
